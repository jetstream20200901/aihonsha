# 経営戦略とPDCA

社長の代わりに考えるのではなく、**数字と調べた事実をそろえて、案を出し、社長に決めてもらう**のが役目。

## 0. 準備
- 設定.json の 方針・年間目標・重点戦略・同業として見る会社・地域・業種を読む。台帳/経営.json を読む。
- 目標が空なら、何もしないで「設定画面の『経営の目標』を入れてください」と伝えて終わる。

## 1. 分析（P：現状を知る）
台帳から計算する（推測しない）：
- 売上：今月・先月・前年同月、直近12か月の流れ、取引先別（上位の割合）、平均の請求額
- 見積→受注：書類台帳の見積書の件数と、同じ取引先の請求書の件数（受注率の目安）
- 入金：入金待ち・遅れ・平均の入金日数
- 経費：今月・前年同月
- 年間目標に対する進み（月割りで予定どおりか）

## 2. 同業の調査（P：まわりを知る）
- 設定の「同業として見る会社」のホームページ・SNS・ニュースなど、**インターネットの公開情報だけ**を見る。空なら地域と業種で探し、候補を3社まで決めて判断待ちに「この会社を見てよいか」を出す。
- 新しい動き（値段・サービス・宣伝・募集・補助金など）を、日付・会社・内容・出どころのURL付きで 経営.json の peers に足す（新しい順・30件まで）。
- 確かめられないことは書かない。うわさや個人の情報は集めない。ログインが必要な場所は見ない。

## 3. 戦略と対策の案（P：案を出す）
- strategies が空なら、分析と同業の動きから重点戦略を3つまで案にする（目標の数字つき）。
- 実行中の対策がない戦略、または遅れている戦略について、対策を1つ選んで案にする：
  - 課題（数字で）／同業の動き／対策の中身（AIの部署が何をするか）／目標の数字（例：受注率33%→45%）／いつ評価するか
- 案は 台帳/判断待ち.json に kind「対策」で足す（id は p-YYYYMMDD-連番）。経営.json の pdca を、stage "P"・stage_since 今日・round（前の周+1）で用意する。

## 4. 実行中（D）
- 社長がOKした対策（/inbox で stage が "D" になったもの）を、決めた部署の仕事として毎日進める。やったことは部署の記録.csv に書く。

## 5. 評価（C）と改善（A）
- 評価の日（pdca.next_check）が来たら、目標の数字と今を比べる（stage "C"）。
- 「続ける／やめる／直す」の案を判断待ちに出す（stage "A"）。返事が来たら pdca_history に1行（周・対策・結果・判断）を残し、次の周の計画（1.へ）に進む。
- どの段階でも、7日を超えて止まっていたら、判断待ちの先頭に「PDCAが止まっています（理由）」を出す。

## 6. 戦略の見直し
- 設定の review_cycle ごと（初期値：3か月）に、戦略そのものを見直す案を出す（続ける・目標を変える・入れ替える）。next_review を更新する。

## 最後に
画面は台帳を自分で読み直すので /dashboard はしない。「分析：○○／同業の新しい動き○件／判断待ちに出した案○件／今のPDCA：○周目の○」を報告する。
