# 準備の診断（読むだけ）

## 手順
次を順に確かめ、最後に表で報告する。**ファイルの作成・変更・削除はしない。** 足りない物は、直し方を書くだけにする。

1. **フォルダ**：00_受付箱／10_請求書／11_見積書／12_契約書／13_領収書・経費／20_議事録／30_規程・マニュアル／90_その他／台帳／画面 があるか。
2. **会社のルール**：CLAUDE.md があるか。「○○」が残っていないか（残っていれば、自社の内容に書き換えるよう伝える）。 最後に「@./仕組み/AI本社の基本ルール.md」の1行があり、仕組み/AI本社の基本ルール.md があるか（無ければ、新しい版の ZIP の「アップデート」を使うよう伝える）。仕組み/バージョン.txt の版も伝える。
3. **台帳**：台帳/書類台帳.csv・売上台帳.csv・やること.csv があり、1行目の見出しが次と同じか。
   - 書類台帳：受付日,書類の種類,取引先,書類の日付,金額,期限,ファイルの場所,メモ
   - 売上台帳：請求日,請求番号,取引先,内容,金額,入金期限,入金日
   - やること：期限,内容,担当,状態
   文字コードが UTF-8（BOM付き）か（Excel で保存し直して Shift_JIS になっていないか）。
4. **スキル**：.claude/skills の中に intake・dashboard・deadlines・invoice・minutes・weekly-report・month-end・find-doc・reply・tidy-csv があるか。
5. **請求書ひな形**：30_規程・マニュアル/請求書ひな形.xlsx があるか。「（自社名）」「（住所）」「（銀行名」が残っていれば、「請求書を作る前に、一度だけ自社の情報を書き込んでください」と伝える（練習用の会社では不要）。
6. **画面**：画面/dashboard.html があり、中の `<script id="company-data" type="application/json">` のデータが正しい JSON か。
7. **道具**：Git と Python が使えるか（`git --version`、`python --version` または `py --version` を実行して確かめるだけ）。無くても基本の仕事はできるが、表の計算を正確にするには Python があるとよい、と伝える。
8. **置き場所**：このフォルダのパスに OneDrive／Google Drive／iCloud が含まれていれば、「そのフォルダを『常にこのデバイスに保存』（オフラインで使える）にしてください。クラウドだけにあるファイルは読めないことがあります」と伝える。
9. **入れてはいけない物**：ファイル名に「パスワード」「マイナンバー」「口座」「password」が入ったファイルがないか（中身は開かない）。あれば、このフォルダの外に移すよう伝える。

## 報告の形
| 確かめた所 | 結果 | 直し方 |
|---|---|---|
| フォルダ | OK／足りない：○○ | 「○○ フォルダを作ってください」 |

最後に「準備OK：○個／直す所：○個」と1行でまとめ、直す所があれば、一番先にやることを1つだけ書く。

## 守ること
- 読むだけ。直すのは人がOKしてから、別の頼みとして行う。
- ファイルの中身を書き写さない（個人情報が入っている可能性があるため）。
