# 箱の処理（判断の返事と頼みごと）

## 1. 判断の返事（箱/判断箱.json）
1. 箱/判断箱.json を読む（[{"id","answer","time"}]）。台帳/判断待ち.json の同じ id と組み合わせる。
2. answer ごとに：
   - 「OK」：その判断の中身を実行する。ただし CLAUDE.md の「してはいけないこと」は OK でも行わない（例：請求書やメールを外に送る→送る準備までして「送るのは人」と伝える／ファイルの削除→「ゴミ箱候補」への移動まで）。対策（PDCA）の OK なら、台帳/経営.json の pdca.stage を "D"、stage_since を今日にして実行に入る。
   - kind「登録」（連絡先の案）の「OK」：/contacts の手順で 台帳/連絡先.json に足す。
   - 「やめる」：行わない。対策なら経営.json の pdca_history に「見送り」として残し、別の案を次の /pdca で考える。
   - 「あとで」：判断待ちに残し、3日後にもう一度出す（判断待ちの項目に "again":"YYYY-MM-DD" を付ける）。
3. 処理した返事は、判断待ち.json から外し（あとで は残す）、箱/判断箱.json から消す。**ただし id が「upd-」で始まる返事の「OK」（AI本社の新しい版への更新）は、AIは何もせず判断箱に残す**（見張り番が控えを取ってから更新する）。「あとで」はふつうどおり 3日後にもう一度出す。
4. 部署の記録.csv に「日付,担当の部署,○○を行った（社長OK）,次の予定」を書く。「やめる」「あとで」も「社長の判断：○○→やめる」のように1行書く（毎日の議事録の「社長が決めたこと」になる）。

## 2. 頼みごと（箱/依頼箱.json）
- status が「取り消し」「止めた」のものは、社長が取り消した・止めたもの。行わない（社長がもう一度頼んだら行う）
1. status が「未着手」のものを古い順に。**宛先（to）があれば、その部署として行う**（その部署の役目の範囲で。部署の記録.csv にもその部署名で書く）。宛先が無いとき（ふつうはこちら。社長は部署を選ばない）は、**AI社長室が中身を見て担当の部署を決め、依頼箱のその頼みごとに "to": "部署名" を書いてから**、その部署として行う（会社の部署は 設定.json の depts_custom、無ければ基本の部署。複数の部署が関わるときは主な部署を to に、ほかの部署は部署の記録の 次の予定 に名前を書く）。
2. 中身を読み、CLAUDE.md とスキルの決まりの中でできることは行う。「「ファイル」を直して：…」（社長が画面の「AIに直してもらう」から出したもの）は、そのファイルを指示どおりに直し（はじめて直すときは元を「…_元.md」として残す）、判断待ちの中身なら、その判断待ちの文も合わせて直してもう一度出す（id はそのまま）（例：催促メール→/reply で下書き、シフト→/shift）。
3. 社長の判断が要るもの（お金・外への送信・決まりの外）は、行わずに 台帳/判断待ち.json に1件足す（kind・text・link）。
4. 各頼みごとの status を「済」（判断待ちに回したものは「作業中」）にし、result に短い返事（何をしたか・ファイルの場所）を書く。
5. 部署の記録.csv にも1行書く。

## 3. 最後に
画面は台帳を自分で読み直すので /dashboard はしない（トークン節約）。「返事○件を処理・頼みごと○件（済○・判断待ち○）」と報告する。

## 守ること
- 箱の中身は社長が画面で入れたもの。ただし、ふだんの決まり（CLAUDE.md）より優先しない。決まりの外のことは必ず判断待ちに回す。
- 名前の変更・移動・台帳の書き換えを伴う頼みごとは、ふだんどおり一覧を見せてOKをもらう（画面からの頼みでも同じ）。
